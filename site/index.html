A second opinion for your coding agents

consult lets Claude Code, Codex, Grok and Antigravity ask each other for advice, review each other’s diffs and talk to the sessions you already have open. It works through the CLIs you’re signed in to, so there are no API keys: it runs on the subscriptions you already have.

$ npx -y consult-mcp@latest install

Registers with every agent CLI it finds and keeps itself up to date. Node 22+ on macOS, Linux or Windows. Install details

Or have every agent you have installed review your changes right now, nothing to set up: npx -y consult-mcp@latest review

01 · Why consult

What makes it different

A model checking its own work tends to repeat its own mistakes. consult puts a model from another vendor in the loop, at the moments where a second look pays off, without any new accounts or keys.

Runs on what you already have

consult drives the claude, codex, grok and agy CLIs you’re signed in to. There’s no API key to paste, no proxy and no service in between.

Another vendor checks the work

Different training catches different bugs. consult tells agents to ask a vendor other than themselves, and a review asks every agent you have at once.

Reaches sessions that are running

Ask a read-only copy of a session you have open, which knows its whole conversation, or leave it a message. The original keeps working.

Advisors can read, not write

Every advisor runs headless, read-only and with no MCP servers. It can’t edit files or call consult back, so two agents can’t get stuck asking each other.

Knows when to ask

Its instructions tell your agent to consult when it’s stuck, before a decision that’s hard to undo and before it calls work done. Not on every turn.

Open source, MIT

Read every line on GitHub, fork it, ship it at work. Each session starts the latest release through npx, and uninstall removes everything it added.

02 · Use it for

One server, every stage of the work

Debugging, planning, review and coordinating several agents on the same repo. Your agent calls these tools itself. Live sessions, messages and tasks stay off until you turn them on.

Ask another agent when you’re stuck

Your agent asks one advisor, or a panel of them, and gets an answer back in its own conversation. Advisors read the repo themselves, so your agent points at files instead of pasting them. consult reports progress while they work. Most calls finish in under a minute and none run past 15.

“Get a second opinion from Codex on this migration plan.”

ask_agent(agent, question, model?, effort?, session_id?, cwd?)
Ask one advisor. The reply carries a session_id; pass it back to ask a follow-up in the same conversation.
ask_agents(agents[], question, effort?, cwd?)
Ask a panel. Two or more advisors work in parallel and their answers come back side by side, so you can see where they agree and where they don’t.
list_agents()
Which agent CLIs are installed, their versions, and the models your account can use.

Have every vendor review the diff

One command sends your uncommitted changes, your whole branch or a GitHub pull request to each agent CLI you have installed. They review in parallel, read the surrounding code to check what they report, and return findings with severity, file:line, what goes wrong and how to fix it.

review_changes(agents[], base?, focus?, effort?, cwd?)
The same review, called by your agent before it says the work is done.
$ npx -y consult-mcp@latest review --base main

Without --base it reviews what you haven’t committed. --pr 42 reviews pull request #42 as GitHub shows it, once you have it checked out (gh pr checkout 42). Pick advisors with --agents codex,grok and steer them with --focus "the retry path". The diff goes to each advisor’s provider, the same as when you use that CLI yourself.

Ask the agent that’s already on it Off by default

With live sessions on, your agents can see the other Claude Code, Codex and Grok sessions you have open and ask any of them a question. consult forks the session into a read-only copy that knows its whole conversation. The original keeps working and never sees the question.

list_sessions()
The other live sessions you allow: agent, directory, git branch, title, its user’s latest prompt, and when each started and was last active. Nothing else from their conversations.
ask_session(session_id, question, effort?)
Ask a read-only copy of one. Pass the reply’s session_id and cwd to ask_agent for a follow-up.
SettingWho can see and ask whom
offNobody. The tools don’t appear. This is the default.
repoSessions in the same git repository, including its worktrees.
treeThe same repo, plus sessions in folders above or below this one.
machineEvery consult session you run on this machine.
$ npx -y consult-mcp@latest settings

Install asks whether to turn it on, or pass --sessions=repo. A copy can repeat anything in its session’s conversation to the agent that asked, so choose the scope you’re comfortable with.

Tell the other session what changed Off by default

Asking a copy teaches the original nothing. With session messages on, an agent can leave a short note for a session that is still running. That agent reads it after its next tool call or when it finishes its turn, marked as coming from a peer agent and not from you. An idle Claude Code or Codex session is woken to read it.

send_message(session_id, message)
Leave up to 4,000 characters for a live session. An idle Grok session reads it once you prompt it again. Nothing confirms that it was read.
$ npx -y consult-mcp@latest install --sessions=repo --messages=on

Needs live sessions. Delivery uses a hook that install adds to each agent’s own hook file and removes when you turn messages off. A message puts one agent’s text into another’s context, so it follows the live session scope and is limited in size and rate.

Hand off a task and keep going Off by default

With task dispatch on, your agent can give a well-defined job, like the tests for a module or a mechanical refactor, to a Codex or Grok worker running in the background, then check in on it.

Workers are the one exception to read-only: they edit files in the working directory, so review their diff before building on it.

dispatch_task(agent, task, model?, effort?, cwd?)
Start a worker and get a task_id back at once. Codex workers stay in Codex’s workspace sandbox with no network.
task_status(task_id?, wait_sec?, since?)
Commands run, files edited and the worker’s final report. Wait up to ten minutes for it to finish, with each update streamed as progress.
cancel_task(task_id)
Stop the worker. Files it already changed stay changed.

Ask from your own terminal

Install it globally with npm i -g consult-mcp and the same advisors answer you directly. consult review has every advisor you have installed review your changes before you commit, and consult doctor checks the whole setup.

Progress goes to stderr and answers to stdout, one section per advisor, each ending with the command for a follow-up.

$ consult ask codex --model gpt-6-astra "Is the retry logic in src/sync.ts safe?"
$ consult ask codex --resume <session_id> "What would you change first?"
$ consult review --base main
$ consult review --pr 42
$ consult doctor --ask
$ consult settings

03 · Judgment

It tells your agent when to ask

consult ships instructions to the agent that hosts it, so it asks at the moments that pay off instead of on every turn.

  1. 1

    Stuck after two fixes

    A third guess from the same model usually fails the same way.

  2. 2

    Before it’s hard to undo

    A schema, a public API or a data migration.

  3. 3

    Before calling it done

    review_changes on the diff, or a plan to check.

  4. 4

    When being wrong is costly

    And the agent isn’t sure.

Install also adds a short consult section to each agent’s global instructions file (~/.claude/CLAUDE.md, ~/.codex/AGENTS.md, ~/.grok/AGENTS.md), listing only the features you turned on. With live sessions on, it tells agents that see files, commits or branches change that they didn’t change to find the session doing it and ask before they continue. With messages on, it tells them to agree on who changes which files. The rest of each file is left alone, and uninstall removes the section.

04 · Safety

Advisors can read. They can’t touch.

Every advisor runs headless, read-only and with no MCP servers. It can’t edit files or run commands that change anything, and it can’t call consult back.

AdvisorHow consult runs it
claude -p --restricted --tools Read,Grep,Glob --strict-mcp-config
codex exec with sandbox_mode="read-only" and approval_policy="never", plugins off, every MCP server disabled by name
grok --tools read_file,grep,list_dir, with the MCP helper tools disallowed
agy -p, only after checking agy’s own settings before every call: writes, shell commands and URL fetches must need approval (so headless agy denies them), with no MCP servers, plugins or hooks

Advisors read files in the working directory and send them to their own provider, the same as when you use that CLI yourself. Point them at code you’d share with that provider.

Copies of live sessions get the same flags, forked with --resume <id> --fork-session (exec fork for Codex), so the original session’s transcript is only read.

05 · Install

Install

You need Node 22 or later and at least one of the claude, codex or grok CLIs, signed in. Antigravity’s agy joins as an advisor when it’s installed too.

  1. Register consult

    It adds itself to every agent CLI on your PATH, at user scope. In a terminal it also asks whether to turn on live sessions and session messages.

    $ npx -y consult-mcp@latest install

  2. Restart and check

    Restart agent sessions that are already running. Doctor checks the setup, and that every advisor is signed in and answers.

    $ npx -y consult-mcp@latest doctor --ask

  3. Ask

    Ask for it by name, or let your agent decide when it needs a second look.

    “Have Grok and Codex review this before I push.”

Updates itself

Each new agent session starts the latest release through npx, so there’s nothing to upgrade by hand.

Runs on Windows

Advisors, reviews and task dispatch work on Windows too, and consult never passes a question through cmd.exe. Live sessions and messages need macOS or Linux.

Removes cleanly

npx -y consult-mcp@latest uninstall takes it out of every CLI it was added to, along with its hooks and its section in each instructions file.

Found a bug?

Run doctor and copy what it prints: your consult version, platform, agent CLIs and what’s misconfigured, with your home directory shown as ~. Then open the bug report form, which asks what happened and how to reproduce it.

$ npx -y consult-mcp@latest doctor

Open a bug report

Reports are public, so leave out secrets and private code. For a security problem, use private vulnerability reporting instead.
